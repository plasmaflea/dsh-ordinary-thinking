# 示例：🧪 倒推图·模拟（单跑一次，结果是"歪打正着"）

> 技能 id：`presupposed-answer-hypothesis-backderivation-simulation`
> 本题面在 5 个候选假设里，真实原因（硬盘剩余空间不足）**从未进入候选集**。

## 输入

> 笔记本剪视频的时候风扇狂转、越剪越卡，是为什么？

## 产物

```
[🧪 倒推图·模拟] 题面：剪视频时风扇狂转、越剪越卡，为什么？
     观察对象：一个没学过排查方法的人，先有直觉、再补理由。

| # | H | E+ | E± | 偏差处置 | 仍成立 | 通道 |
|---|----|----|----|----------|--------|------|
| 1 | CPU 太弱，扛不住编码 | CPU 占用应接近 100% | 实测 ~40% | 解释掉：「任务管理器读数不准」 | 是 | — |
| 2 | CPU 太弱 | 同型号机器不该有这问题 | 同事同型号不卡 | 改边界：「我这台体质差」 | 边界内是 | — |
| 3 | 散热不行，高温降频 | 核心温度应 >90℃ | 实测 78℃ | 改边界：「测温偏低，算它 85+」 | 是 | — |
| 4 | 散热不行 | 清灰后应明显改善 | 清灰后确实好转 | 采纳（没做对照） | 是 | A |
| 5 | （结论）就是散热问题 | — | 好转了 | — | — | L |

结果：表面正确——处理后确实不卡了
通道归因：A 迟到调整 主导（CPU 弱 → 体质差 → 散热差，两次都是改边界，不是改假设）
          L 运气 次要（"积灰导致过热"先验很强，本就大概率成立）
          真推理 0（全程没有一次真正的证伪动作）
失效面：真实原因是硬盘剩余空间不足 → 缓存写入抖动。这条永远不会被检验到，
        因为「改边界」只在原假设的邻域里平移，扩不出候选集，而候选集以外的东西，
        倒推法在结构上就看不见。
```

## 这次"对了"说明什么

三件事，缺一不可地说：

1. **它对了，但靠的不是方法**——两次偏差都是「改边界」处置的，本质是把一次错的假设挪到它恰好为真的那个邻域里。这叫迟到调整，不叫推理。
2. **它错得也很快**——如果真实原因是候选集之外的（磁盘、后台同步、编码器 bug），这套流程会一直自洽地走到底，且永远不会报警。
3. **它的成本极低**——5 步、零对照组、不需要建树也不需要列负边。这就是它能存活的原因，不是因为它准。

## 多跑模式怎么设计（同一题）

| 设置 | 做法 |
|---|---|
| 固定 | 题面、证据集、处置规则 |
| 随机 | 第 1 步选哪支假设（按先验加权：内存/CPU/散热/磁盘/软件） |
| 次数 | N = 20 |
| 控制组 | 在第 1 步注入一条硬反例（"同型号同事不卡"），看命中率掉多少 |
| 记录 | p̂、通道分解、平均步数 |

预期（未实测，属假设，不是结论）：p̂ 不低，但通道分解里 A + L 会占大头，注入硬反例后 A 通道被掐断，p̂ 会明显下降——这正是「普通人的成功率依赖先验强度，而非方法强度」的可测形式。
